# Журнал решений

Каждая запись содержит дату, принятое решение и причину. Новые записи добавляются по мере принятия решений.

## 2026-09-17 — первое направление: обработка мемов

- Приложение работает локально в Windows без обязательного сервера: пользователь запускает пакетную обработку вручную, поэтому постоянная инфраструктура не нужна.
- Один запуск обрабатывает максимум 20 Telegram-постов: ограничение задаёт понятный объём ручного запуска и относится к постам, включая альбомы, а не к отдельным картинкам.
- Telegram-пост принят единицей надёжности: результат всех изображений поста должен быть завершён как единое целое, чтобы альбом не остался частично обработанным.
- Исходный пост удаляется из Telegram только после фиксации результатов и локального контрольного состояния: при сбое незавершённый вход остаётся доступным для повторной попытки.
- SQLite используется для состояния, нумерации и защиты от дублей, но не как постоянная очередь: Telegram остаётся единственной входящей корзиной, а локальное состояние позволяет завершить удаление уже обработанного поста без повторных результатов и API-запросов.
- Восстановление после аварии обязательно: Stop, закрытие программы, сбои сети/API и питания не должны повреждать готовые результаты, переводы или нумерацию.
- Код автоматизации не начинается до фиксации спецификации и плана: сначала нужно согласованно описать границы обработки и восстановления.
